## Patches

| Patch | File | SHA-256 of the patch | Change |
|---|---|---|---|
| `0001-cycle-cost.patch` | `Interdata/id16_cpu.c` | `c15f6f76852d9691f4f70cb2e4155cb5fbee066c2fb28a17f30dc905f116ff06` | cycle-cost hooks: `sim_interval -= SX_CYC (op)` after the opcode is decoded instead of `-= 1` before fetch, and `-= SX_CYC_X (op, r1, r2, opnd, cc)` (taken branch, shift count, registers moved) after the operand is decoded, both before the opcode dispatch. Stock defaults are 1 and 0; the engine's table (src/engine/machine/cycles.h, VS-02) is also stock until cycle mode is selected, so S-3 and the oracle traces run with the stock cost. |
| `0004-devices.patch` | `Interdata/id16_sys.c` | `6d5f8ba5ff944681134c515e326c28e20cd8fd6340fd6a177f54f459de9fbe2d` | device registration: under SEASTONES_ENGINE, sim_devices lists only the devices the engine contains (CPU with display, selector channel, PIC, LFC, and our KEYS X'20', DAC X'21', GATE X'22' from src/engine/devices/id_seastones.c, declared extern) and sim_load returns SCPE_NOFNC, so the peripheral files are not linked. |

No patch touches instruction semantics (S-3 GO criterion 4). Patch numbers follow ARCHITECTURE 4.2. Planned patches that turned out not to be needed:

- **0002-emulated-rtc**: Not needed as a patch. id_uvc.c calibrates only through sim_rtcn_init and sim_rtcn_calb, which the shim implements from emulated time (no host clock is ever read), so id_uvc.c is vendored unmodified.
- **0003-idle-in-engine**: Not needed as a patch. id16_cpu.c's wait state calls sim_idle, which the shim implements; S-3 keeps stock behaviour (one interval tick per idle pass, as stock SCP with idling disabled). In cycle mode (VS-02) the shim's sim_idle jumps to the next event instead, which needs no CPU change.
